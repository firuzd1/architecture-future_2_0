# Что делаем с ESB на Camel

Camel - это интеграционный фреймворк, а Kafka - транспорт. Поэтому ESB нельзя просто заменить на Kafka. Сейчас в ESB намешано много всего: маршрутизация, ФЛК, трансформации, ретраи, адаптеры к внешним системам и часть бизнес-логики. Разносим это по отдельным местам.

## Куда уходит каждая функция

| Что сейчас делает ESB | Куда уходит в целевой архитектуре | Чем |
|---|---|---|
| Транспорт и доставка сообщений | Event backbone | Kafka (репликация, acks=all) |
| Маршрутизация точка-точка | топики и подписки, кто подписан тот и получает. Сложная маршрутизация (content-based) остается в интеграционных сервисах | Kafka + Camel в интеграционных сервисах |
| ФЛК - формат | проверка схемы при публикации, невалидное не попадает в топик | Schema Registry |
| ФЛК - логический контроль внутри домена | в сервисе домена-источника, до публикации события. Домен лучше знает свои правила | сервисы доменов |
| ФЛК для внешних данных (фарма, медтехника, партнеры) | на входе в интеграционный шлюз, невалидное в DLQ и на ручной разбор | Integration Gateway (Camel Quarkus) |
| Адаптеры протоколов (SOAP, SFTP-файлы, HL7/FHIR, REST партнеров) | интеграционные сервисы и коннекторы | Camel Quarkus, Kafka Connect |
| Трансформации потоковые (обогащение, маппинг, агрегаты) | потоковая обработка | Kafka Streams в доменах, Flink для витрин |
| Трансформации пакетные (выгрузки, сверки, ночные расчеты, файлы от партнеров) | оркестратор пакетных задач | Airflow + dbt |
| Надежность: ретраи, DLQ, идемпотентность | общие правила платформы: retry-топики, DLQ на каждый топик, идемпотентные консьюмеры по event_id, outbox в продюсерах | Kafka + библиотека-шаблон платформы |
| Надежность: таймауты, circuit breaker к внешним системам | в интеграционных сервисах | Camel (Resilience4j) |
| Оркестрация длинных процессов (рассрочка, возвраты) | саги в доменах-владельцах процесса | сервис домена, при росте - Temporal |
| Бизнес-логика, которая "прилипла" к маршрутам | переносим в сервисы своих доменов, в интеграционном слое бизнес-логики нет | сервисы доменов |
| Мониторинг потоков | трейсинг по correlation_id, метрики лагов консьюмеров | Jaeger, Prometheus, Grafana |

## Что остается от Camel

Camel как фреймворк не выкидываем, он хорош для адаптеров. Но вместо одной центральной шины будут небольшие интеграционные сервисы на Camel Quarkus, у каждого свой владелец и свой деплой. Они только переводят протоколы и форматы, бизнес-логики в них нет.

Центральный ESB выключаем по маршрутам.

## Как переносим

1. Инвентаризация маршрутов Camel: что куда ходит, есть ли там ФЛК, трансформации, бизнес-логика. Помечаем владельца-домен у каждого маршрута.
2. Для маршрута решаем по таблице выше, куда уходит каждая часть.
3. Сначала маршрут работает параллельно: ESB + новая схема, сверяем результаты.
4. Переключаем потребителей, старый маршрут выключаем.
5. Так по маршрутам, начиная с пилотных доменов (фин расчеты, пациентский поток).

## По этапам

| Этап | Что с ESB |
|---|---|
| 1 (0-6 мес) | инвентаризация маршрутов, ACL для пилотных доменов, правила DLQ и ретраев, Schema Registry |
| 2 (6-18 мес) | Integration Gateway для внешних партнеров, Airflow для пакетных задач, перенос маршрутов критичных доменов |
| 3 (18-36 мес) | последние маршруты перенесены, центральный ESB выключен |
