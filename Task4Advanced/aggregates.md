# Агрегаты

Для каждого: в каком контексте, что внутри (границы), какие правила всегда должны выполняться (инварианты) и ключ.

## Пациент
Контекст: Регистрация пациентов (Клиники)
Внутри: ФИО, дата рождения, документы, контакты, согласия на обработку данных
Инварианты:
- один человек = один пациент, проверка дублей по документу
- без согласия на обработку персданных пациента не регистрируем
- удалить нельзя, только архивировать (медицинские требования)
  Ключ: `patient_id` (UUID)

## Визит
Контекст: Пациентский поток (Клиники)
Внутри: пациент, врач, слот, статус, список оказанных услуг, списанные материалы
Инварианты:
- у врача не может быть двух визитов на один слот
- завершить можно только визит в статусе "идет"
- после завершения список услуг не меняется, исправления только новой корректировкой
  Ключ: `visit_id`, ссылки на `patient_id`, `doctor_id`

## Исследование
Контекст: Медкарты и исследования (Клиники)
Внутри: пациент, тип исследования, файлы, заключение врача, заключение ИИ
Инварианты:
- исследование всегда привязано к пациенту и визиту
- итоговое заключение подписывает врач, ИИ только дает рекомендацию
- данные не выходят за пределы домена, наружу уходят только id и статус
  Ключ: `study_id`

## Анализ ИИ
Контекст: ИИ-диагностика
Внутри: ссылка на исследование, версия модели, результат, уверенность, статус
Инварианты:
- один запуск = одна версия модели, ее нельзя поменять после старта
- результат с уверенностью ниже порога помечается на ручную проверку
  Ключ: `analysis_id`, ссылка на `study_id`

## Счет
Контекст: Расчеты за услуги (Финтех)
Внутри: пациент, позиции по услугам, сумма, валюта, статус (выставлен / частично оплачен / оплачен / отменен)
Инварианты:
- сумма = сумма позиций
- сумма оплат не больше суммы счета
- оплаченный счет нельзя отменить, только возврат отдельной операцией
  Ключ: `invoice_id`, ссылка на `visit_id`

## Платеж
Контекст: Счета и платежи (Финтех)
Внутри: счет списания, счет зачисления, сумма, статус
Инварианты:
- нельзя списать больше доступного остатка
- платеж проводится один раз (ключ идемпотентности)
  Ключ: `payment_id`, `idempotency_key`

## Кредитный договор
Контекст: Кредиты (Финтех)
Внутри: клиент, сумма, ставка, срок, график платежей, статус
Инварианты:
- договор создается только после положительного скоринга
- условия после подписания не меняются, только допсоглашением
- сумма в графике = тело кредита + проценты
  Ключ: `loan_id`, ссылка на `client_id` (= `patient_id`, если клиент и пациент один человек)

## Складская позиция
Контекст: Склад и инвентарь (Головной офис)
Внутри: товар, клиника, остаток, минимальный уровень
Инварианты:
- остаток не может быть меньше нуля
- при остатке ниже минимума публикуется событие ровно один раз, пока запас не восстановят
  Ключ: `sku` + `clinic_id`

## Сотрудник
Контекст: Персонал (Головной офис)
Внутри: ФИО, должность, клиника, график, допуски
Инварианты:
- врач без действующего допуска не может быть назначен на прием
  Ключ: `employee_id`
